Potential Uninstall Entry Concealment

edit

Identifies execution of the Hide From Uninstall List utility or a registry change that marks an installed application as a system component, causing Windows to omit it from Programs and Features. Adversaries may use either method to conceal remote-access, security, or other software.

Rule type: eql

Rule indices:

  • logs-endpoint.events.process-*
  • logs-endpoint.events.registry-*
  • logs-windows.sysmon_operational-*
  • winlogbeat-*

Severity: medium

Risk score: 47

Runs every: 5m

Searches indices from: now-9m (Date Math format, see also Additional look-back time)

Maximum alerts per execution: 100

Investigation guide

edit

Triage and analysis

Investigating Potential Uninstall Entry Concealment

Possible investigation steps

  • Which detection path generated the alert?
  • Focus: review event.category, process.pe.original_file_name, registry.path, registry.value, and registry.data.strings.
  • Implication: a process event identifies HideUL execution but does not prove that an application was hidden. A registry event setting SystemComponent to 1 establishes the concealment change but does not by itself identify the utility.
  • Which application was targeted, or did the HideUL execution progress to a concealment write?
  • Focus: for a registry alert, resolve the uninstall subkey’s DisplayName, Publisher, DisplayVersion, and UninstallString from endpoint state, software inventory, or adjacent events. For a process alert, review same-process events for a SystemComponent write. !{investigate{"description":"","label":"Events for the same process","providers":[[{"excluded":false,"field":"host.id","queryType":"phrase","value":"{{host.id}}","valueType":"string"},{"excluded":false,"field":"process.entity_id","queryType":"phrase","value":"{{process.entity_id}}","valueType":"string"}]],"relativeFrom":"now-1h","relativeTo":"now"}}
  • Implication: hiding remote-access, security, monitoring, or unfamiliar software raises concern. A process-only alert without a corresponding write remains an execution signal; absent registry telemetry is unresolved, not evidence that no application was hidden.
  • What binary and launch chain initiated the execution or registry change?
  • Focus: review process.executable, process.command_line, process.hash.sha256, process.parent.executable, and user.name; use the process entity or ancestry to recover missing launch context.
  • Implication: a renamed binary, user-writable path, unexpected parent, remote-management launcher, or unfamiliar hash raises concern. A stable internal path or known hash identifies the binary but does not by itself establish a recognized administrative workflow.
  • Did the same process modify other uninstall entries or removal controls?
  • Focus: review registry events for the alert’s host.id and process.entity_id, including registry.path, registry.value, registry.data.strings, and event.action.
  • Implication: multiple hidden applications, deletion of uninstall entries, or writes to NoRemove or NoModify increase scope. HFULOption is context about HideUL bookkeeping and is not evidence of concealment by itself.
  • Does the target or launch context connect this operation to an active remote-access session or broader defense evasion?
  • Focus: use the same-host related-alert view to find remote-access installation, interactive-session, or defense-evasion alerts. Separately correlate available RMM audit or session records by host, user, and time. !{investigate{"description":"","label":"Alerts associated with the host","providers":[[{"excluded":false,"field":"event.kind","queryType":"phrase","value":"signal","valueType":"string"},{"excluded":false,"field":"host.id","queryType":"phrase","value":"{{host.id}}","valueType":"string"}]],"relativeFrom":"now-48h/h","relativeTo":"now"}}
  • Implication: an active remote session, recent remote-access installation, or another defense-evasion alert increases priority. Missing product or session telemetry is unresolved, not benign.
  • If local evidence remains suspicious, is the same utility hash, writer, or hidden product present on other hosts?
  • Focus: search for the recovered process.hash.sha256, writer executable, and target uninstall subkey or resolved product identity across endpoints, keeping the initial time range close to the alert before broadening.
  • Implication: repeated execution or concealment on additional hosts raises concern for coordinated activity. Recurrence limited to a recognized software-management or hardening pattern on expected hosts lowers concern but is not clearance by itself.
  • Escalate when the matched signal, target application, writer, or surrounding activity indicates concealment of remote-access, security, or unfamiliar software, or other high-risk context. Close only when the exact execution or registry change matches a named change record; otherwise preserve the evidence and keep the case unresolved.

False positive analysis

  • Application installation, update, packaging, shared-device, kiosk, lab, or administrative hardening workflows may intentionally set SystemComponent. Confirm the matched branch, exact uninstall target when present, binary hash and path, initiating identity, parent process, host group, and change window against the workflow record.

Response and remediation

  • If confirmed benign, document the matched signal, target application when present, and execution context, and reverse any temporary containment.
  • If suspicious but unconfirmed, preserve the alert source event, HideUL or writer binary and hash, launch lineage, target uninstall subkey and sibling values when present, and related remote-session evidence. Restrict the suspected session first; isolate the host only when the evidence and asset role justify it.
  • If confirmed malicious, isolate the host when operationally safe, disable the unauthorized remote-access channel, and contain the associated account or session. Terminate the recovered process only after preserving its entity ID, command line, hash, and available registry evidence.
  • Restore the affected uninstall registration through the owning product’s supported installer or a verified pre-change value. Do not delete the application or registry key before preserving evidence and confirming whether the hidden software itself is authorized.
  • Hunt for the same HideUL or writer hash, launch lineage, uninstall subkey, and hidden product on other hosts. Remove confirmed malicious tooling and persistence only after scope is established, then retain process and registry telemetry needed to detect recurrence.

Rule query

edit
any where host.os.type == "windows" and
(
  (
    event.category == "process" and event.type == "start" and
    (process.name : ("HideUL.exe", "HideUL_x64.exe") or ?process.pe.original_file_name : "HideUL.exe")
  ) or
  (
    event.category == "registry" and event.type == "change" and
    registry.value : "SystemComponent" and
    registry.path : (
      "*\\Software\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\*",
      "*\\Software\\WOW6432Node\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\*"
    ) and
    registry.data.strings : ("1", "0x00000001") and
    not registry.path : "*Microsoft EdgeWebView\\SystemComponent" and
    not (
      registry.path : "*\\{*}\\SystemComponent" and
      process.executable : ("?:\\Windows\\System32\\msiexec.exe") and
      user.id : "S-1-5-18"
    )
  )
)
