Workload identity federation

edit

Use workload identity federation to read Event Hubs and write Blob checkpoints from Kubernetes, including clusters outside Azure, without client secrets or connection strings.

Before starting Filebeat, complete these steps.

  1. Configure a Microsoft Entra app registration or user-assigned managed identity to trust your cluster’s OpenID Connect (OIDC) issuer, service account subject, and token audience. See Configure an app to trust an external identity provider.
  2. Project a Kubernetes service account token with audience api://AzureADTokenExchange into the Filebeat container. Kubernetes rotates the file as tokens expire, so keep it mounted for the lifetime of the input.
  3. Grant the identity the required Event Hubs and Blob Storage permissions.
  4. Provide each identity value through the input setting or the corresponding environment variable. A nonempty input setting takes precedence.
Input setting Environment variable

tenant_id

AZURE_TENANT_ID

client_id

AZURE_CLIENT_ID

federated_token_file

AZURE_FEDERATED_TOKEN_FILE

The Event Hubs consumer and Blob checkpoint storage use the same identity settings. For sovereign clouds, set authority_host. The input reads the projected token directly without a managed identity endpoint or sidecar.
