Known issues

edit

  • Clusters which use the s3 repository type with storage that is not fully compatible with Amazon S3 may report errors such as Missing required header for this request: Content-MD5 on DeleteObjects requests after upgrading to Elasticsearch 8.19.17. This may prevent creating or updating a repository, verifying a repository, repository analysis, and may leave unreferenced objects in place after deleting a snapshot.

    Amazon S3 and third-party storage products that are fully compatible with Amazon S3 are not impacted. Using storage which is not fully compatible with Amazon S3 with the s3 repository type puts your snapshot data at risk. Review S3-compatible services for further guidance about third-party S3-compatible services.

    If you are using an affected third-party storage product, seek a fix for this incompatibility with Amazon S3 from its supplier. As a temporary workaround, upgrade to at least Elasticsearch 8.19.24 and set s3.client.CLIENT_NAME.legacy_content_md5 in the S3 client settings to true for the affected client.

  • Clusters which use the s3 repository type with storage that is not fully compatible with Amazon S3 may report errors such as The Content-SHA256 you specified did not match what we received or The provided 'x-amz-content-sha256' header does not match what was computed on upload requests after upgrading to Elasticsearch 8.19.17. This may prevent creating a snapshot and repository analysis.

    Amazon S3 and third-party storage products that are fully compatible with Amazon S3 are not impacted. Using storage which is not fully compatible with Amazon S3 with the s3 repository type puts your snapshot data at risk. Review S3-compatible services for further guidance about third-party S3-compatible services.

    If you are using an affected third-party storage product, seek a fix for this incompatibility with Amazon S3 from its supplier. As a temporary workaround, upgrade to at least Elasticsearch 8.19.26 and set s3.client.CLIENT_NAME.unsafely_omit_request_body_checksums in the S3 client settings to true for the affected client. Do not set the AWS_REQUEST_CHECKSUM_CALCULATION environment variable or the -Daws.requestChecksumCalculation system property as these have no effect from Elasticsearch 8.19.26 onwards.

  • The create trained model API enforces overly restrictive input limits that may reject valid requests. A change in 8.19.17 introduced caps on description, tags, prefix_strings.ingest_prefix, prefix_strings.search_prefix, input.field_names, default_field_map, and metadata. These limits are too low for some existing use cases, including the Problemchild and DGA Security integrations, which require more than the 100-field cap on input.field_names.
