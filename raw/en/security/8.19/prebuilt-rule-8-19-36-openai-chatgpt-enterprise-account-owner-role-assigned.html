OpenAI ChatGPT Enterprise Account Owner Role Assigned

edit

Detects ChatGPT Enterprise audit events where a user role is updated to account-owner. Account owners control workspace membership, connectors, usage limits, and other security-sensitive settings. An adversary who promotes a compromised account to owner gains durable control-plane access.

Rule type: esql

Rule indices: None

Severity: high

Investigation guide

edit

Triage and analysis

Investigating OpenAI ChatGPT Enterprise Account Owner Role Assigned

A user role was updated to account-owner. Account owners control workspace membership, connectors, usage limits, and other security-sensitive settings.

Escalate when the promotion lacks change management, the actor is unexpected, or privileged activity follows. Close as a false positive for planned ownership transfers with an approved request.

Possible investigation steps

  • Identify the actor (user.id / user.email) and the target user in openai_chatgpt_enterprise.audit_log.action_data.
  • Confirm whether a ticket or change request authorized the promotion.
  • Review invites, usage-limit changes, plugin or feature policy updates, and log exports after the promotion.
  • Check authentication anomalies for the actor or target around the same time.

False positive analysis

  • IT administrators legitimately promote users to account-owner during staffing or ownership changes when the request is approved.

Response and remediation

  • Downgrade unauthorized owners, revoke sessions, and audit other IAM changes by the same actor.

Setup

edit

Setup

This rule requires the OpenAI ChatGPT Enterprise integration to collect compliance logs into Elasticsearch.

https://www.elastic.co/docs/reference/integrations/openai_chatgpt_enterprise

Rule query

edit
from logs-openai_chatgpt_enterprise.audit_log-* metadata _id, _version, _index
| where
    data_stream.dataset == "openai_chatgpt_enterprise.audit_log" and
    event.action == "user_role_updated" and
    (
        openai_chatgpt_enterprise.audit_log.action_data.new_role == "account-owner" or
        openai_chatgpt_enterprise.audit_log.action_data.role == "account-owner"
    )
| keep
    _id, _version, _index, @timestamp, event.action, event.outcome, user.id, user.email, source.ip,
    source.geo.country_iso_code, openai_chatgpt_enterprise.audit_log.action_data.role,
    openai_chatgpt_enterprise.audit_log.action_data.new_role,
    openai_chatgpt_enterprise.audit_log.action_data.previous_role,
    openai_chatgpt_enterprise.audit_log.action_data.user_id,
    openai_chatgpt_enterprise.audit_log.action_privilege,
    openai_chatgpt_enterprise.audit_log.actor.type, data_stream.*
