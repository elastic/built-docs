ESXi Syslog Remote Host Reset

edit

Detects the ESXi remote syslog destination being cleared with --reset=loghost. The loghost is where host logs are forwarded for retention and detection. Clearing it keeps later commands on the host only, so an external collector stops receiving them.

Investigation guide

edit

Triage and analysis

Investigating ESXi Syslog Remote Host Reset

Remote syslog is often the only copy of ESXi shell history that leaves the host. --reset=loghost drops that destination. Obfuscated commands in the same reports decode to this exact esxcli line.

Possible investigation steps

  • Read message for a literal esxcli line or an obfuscated line that still contains reset=loghost.
  • Run or review esxcli system syslog config get and confirm whether Remote Host is empty.
  • Correlate with firewall, SSH, and VM shutdown commands from the same session.

False positive analysis

Collector migrations reset the old loghost and then set a new one. An empty loghost that stays empty is not a migration.

Response and remediation

  • Restore the collector: esxcli system syslog config set --loghost=<collector> and reload syslog.
  • Pull local shell.log, hostd.log, and auth.log before they rotate. The gap while loghost was empty will be missing from the collector.
  • If the reset was unauthorized, isolate the host.

Setup

edit

Setup

This rule requires ESXi host logs collected by the Elastic vSphere integration: https://www.elastic.co/docs/reference/integrations/vsphere

Rule query

edit
data_stream.dataset:vsphere.log and message:("syslog config set" and ("--reset loghost" or "--reset=loghost" or "reset=loghost"))
