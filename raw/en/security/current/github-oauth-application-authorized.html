GitHub OAuth Application Authorized

edit

Detects when a user authorizes a GitHub OAuth application. Stolen OAuth grants persist after password changes until revoked and can clone or ZIP private repositories. This is not a GitHub App installation (integration_installation.create).

Rule type: esql

Rule indices: None

Severity: low

Risk score: 21

Runs every: 5m

Searches indices from: now-9m (Date Math format, see also Additional look-back time)

Investigation guide

edit

Triage and analysis

Investigating GitHub OAuth Application Authorized

oauth_authorization.create is a user grant of an OAuth App. It is distinct from installing a GitHub App. After a grant, look for git.clone or repo.download_zip with programmatic_access_type of OAuth access token.

Possible investigation steps

  • Identify user.name, github.oauth_application_name / github.oauth_application_id, github.actor_ip, and github.user_agent.
  • Confirm the app is approved by the organization. Review requested scopes.
  • Pivot to clone, ZIP, and api.request activity from the same user shortly after the grant.

False positive analysis

  • First-time login to an approved CI, IDE, or SaaS integration.

Response and remediation

  • If unauthorized, revoke the OAuth grant and the application’s tokens, then force a password reset and session invalidation.
  • Review org third-party application restrictions.

Rule query

edit
from logs-github.audit-* metadata _id, _index, _version
| where
  event.module == "github" and data_stream.dataset == "github.audit"
    and event.action == "oauth_authorization.create"
| keep
    _id,
    _index,
    _version,
    @timestamp,
    event.action,
    user.name,
    github.org,
    github.repo,
    github.actor_ip,
    github.hashed_token,
    github.oauth_application_name,
    github.oauth_application_id,
    github.programmatic_access_type,
    github.user_agent,
    github.name
